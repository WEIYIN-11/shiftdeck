# shiftdeck ｜簡報手排檔

**別人的 AI 簡報是自排，這個是手排——你想換檔，自己換。**

頁型用挑的、動畫用點的、單頁重做不用等全份。

> 本專案使用 [ppt-master](https://github.com/hugohe3/ppt-master)（MIT）的 SVG → 原生 PPTX 編譯引擎，
> 在其上新增：職場頁型庫、動畫選擇器、單頁重生成、繁體中文介面。
> 引擎版本鎖定於 [`engine.lock`](./engine.lock)。

---

## 這是什麼

AI 簡報工具現在都很聰明——你給材料，它給你一份完整的簡報。問題在**它決定了一切**：版面它挑、動畫它配、你想改一頁就得用文字跟它拉扯，改完還要等整份重跑。

shiftdeck 把三個選擇權還給你：

| 你想做的事 | 現在怎麼做 |
|---|---|
| 這頁我要 SWOT 版面 | 從頁型庫**挑**，不是描述給 AI 聽 |
| 這個標題要用飛入 | **點**元素選效果，即時預覽單一元素的動畫 |
| 第 5 頁重做 | 只重跑第 5 頁，不用等全份 |

底層仍然是 ppt-master 的編譯引擎，所以輸出還是**原生可編輯的 .pptx**——真正的 PowerPoint 形狀、文字框、圖表，不是一頁一張圖。

## 安裝

需要 Python 3.10+ 與 Git。

```bash
git clone https://github.com/Coolkidlab-Yin/shiftdeck.git
cd shiftdeck
python scripts/setup.py
```

`setup.py` 會取得鎖定版本的引擎並套用覆蓋層。引擎本身不進版控（14,000+ 檔案），由安裝時取得。

## 使用

在有 agent 能力的 AI 工具（Claude Code、Cursor、Codex CLI 等）裡打開本資料夾，在對話裡說要做什麼：

```
用 shiftdeck 做一份簡報。材料：C:\...\Q3報告.pdf
給主管看的季度檢討，12 頁以內，繁體中文。
```

四個頁型怎麼挑、動畫套組怎麼選、單頁重做怎麼觸發——完整步驟見 [使用說明](./docs/usage.md)。

## 頁型庫

版面是固定骨架 ＋ 依內容量伸縮的槽位契約。生成前用講的（「第 3 頁用 SWOT」），生成後用挑的（預覽編輯器裡換頁型 → 只重畫那一頁）。

| 頁型 | 彈性 |
|---|---|
| 對比頁 | 3–5 個面向 |
| 流程圖 | 3–7 節點 |
| SWOT | 固定 4 象限 |
| KPI 儀表板 | 3–6 指標 |

新增一個頁型＝**一個資料夾（骨架 SVG ＋ 契約）＋ `catalog.json` 一筆**，不必改任何程式碼。

## 動畫

引擎本身有 203 個動畫效果的機器可讀註冊表，但確認頁只給了一個布林開關——**能力存在，介面缺失**。shiftdeck 補上介面，分兩層：

**Deck 套組**——確認頁選一次，整份套用，匯出時自動展開，不必再下任何指令。

| 套組 | 動效 | 場合 |
|---|---|---|
| 專業沉穩 | 以淡入為主、無路徑動畫、時長偏短 | 對外商務簡報，動效不與論點爭注意力 |
| 輕快活潑 | 適度飛入與縮放、逐項揭示 | 內訓與分享，用節奏帶動講述 |
| 極簡無干擾 | 只有頁間轉場，頁內完全不動 | 資料密集、供閱讀而非表演 |

**元素微調**——預覽編輯器裡點元素改效果與順序，每類只放 6–8 個常用效果。**可以只預覽單一元素的動畫**（PowerPoint 必須播放整頁才看得到）。改完可存成自己的套組到 `overlay/animations/user/`，與內建的並列在清單裡。

匯出的是 OOXML 原生動畫節點，不是模擬。

## 單頁重生成

預覽編輯器裡選一頁 →「換頁型」或「重畫本頁」→ 伺服器只記錄請求 → 回對話說「重畫這一頁」→ AI 只重寫那一支 SVG → 單頁品質檢查 → 增量打包 → 匯出。

**實測**：4 頁專案全量 267s vs 單頁 70s＝**26%**。省下的是最貴的那段——AI 只重畫一頁。

**誠實的邊界**：匯出仍是全量的。引擎的釋出閘門要求整份 `svg_output/` 有一份通過的品質報告才准匯出，這條不繞。純文字專案上，單頁路徑的機械部分甚至比全量慢 0.94 秒（多了一道單頁檢查）；`--pages` 增量打包的價值要在有圖的專案才顯現（20 頁含圖：3.007s → 0.768s）。

## 品質閘門

每個匯出物都要過兩道，缺一不可：

```bash
python scripts/visual_check.py projects/<專案>/exports/<檔名>.pptx
```

`svg_quality_checker`（引擎內建）算幾何——抓得到座標溢界。`visual_check.py` 用 LibreOffice **真實渲染**成逐頁 PNG——抓得到真實字型撐破方框。

這道閘門是被真實的坑逼出來的：checker 對一頁跑版的簡報回報 0 errors，人眼一開檔案就看到文字撐出格線。幾何算不出字型度量。

## 架構

```
shiftdeck/
├── engine.lock      引擎版本鎖定（repo + commit + patched_files 契約）
├── overlay/         所有客製化——純加法，不改引擎
│   ├── i18n/        繁體中文字典
│   ├── pagetypes/   頁型庫（骨架 + 槽位契約 + 選單目錄）
│   ├── animations/  動畫套組（含 user/ 放你自己衍生的套組）
│   ├── regen/       單頁重生成（選取狀態通道 + 快路徑 CLI）
│   └── patches/     引擎修補（唯一破例，每一筆都是合併債務）
├── scripts/         安裝、繁中檢查、視覺驗證
├── projects/        你的簡報（不進版控）
└── vendor/          引擎（不進版控，安裝時取得）
```

設計原則：**引擎目錄保持乾淨、可整包替換**。上游更新時只需換掉 `vendor/`，覆蓋層自動繼承。

覆蓋層拿掉會怎樣？已實測：把 `overlay/` 改名後，編輯器照常啟動、新 API 全回 `available:false`／404、匯出與打包都正常且不吐任何 shiftdeck 訊息——**乾淨退回上游行為**。

# 階段 4：單頁重生成

> **前置：階段 2 必須完成**（有頁型才有東西可換），階段 1 完成後對 UI 較熟悉。
> ⚠️ **本階段是唯一必須 patch 引擎內部流程的工作**，不確定性最高，故排最後——前三階段已是可用產品，這裡卡住不會拖垮專案。

## 目標

在預覽編輯器裡改一頁（換頁型／要求重畫）→ **只重跑該頁** → 重新匯出，不用等全份。

## 現況（要改變的東西）

引擎目前的流程是全量的：修改後回到對話 → Executor 重畫 → 全部頁面重跑品質檢查 → `finalize_svg.py` 全量 → `svg_to_pptx.py` 全量重匯出。一頁改動的代價是整份的代價。

相關路徑（`vendor/ppt-master/skills/ppt-master/`）：

| 檔案 | 角色 |
|---|---|
| `workflows/generate-pptx.md` | Step 6 執行、Step 7 匯出的流程規範 |
| `scripts/svg_quality_checker.py` | 品質檢查，支援 `--stage first-page`（**已有單頁概念，是重要線索**） |
| `scripts/finalize_svg.py` | 產生自包含預覽 |
| `scripts/svg_to_pptx.py` | 匯出 PPTX |
| `scripts/svg_editor/server.py` | 預覽編輯器後端（1,389 行） |
| `workflows/stages/live-preview.md` | 註解迴路的既有規範 |

## 設計要點

**借用 open-slide 的選取狀態設計**（只借設計，不移植程式碼——那是 React/Vite 生態，與此處的 Python／原生 JS 不相容）：

> dev server 把「使用者現在選取了什麼」寫進一個狀態檔，AI 讀它就知道「這個」「這一頁」指的是誰。

具體要建立的東西：

1. **選取狀態通道**：預覽編輯器把當前選取（頁碼、元素 id）寫進 `<專案>/live_preview/current.json`
2. **單頁重生成入口**：編輯器提供「換頁型／重畫本頁」動作，寫出一份重生成請求
3. **AI 端流程**：只重寫該頁 SVG → 只對該頁跑品質檢查 → 增量 finalize → 重新匯出
4. **匯出增量化**：這是最難的一步。先確認 `svg_to_pptx.py` 是否支援單頁替換；若不支援，退而求其次——只重跑該頁的 SVG 產出，匯出仍為全量但省下最貴的 AI 重畫成本

## 驗收標準

- [ ] 預覽編輯器可對任一頁觸發「換頁型」，選單來自階段 2 的頁型庫（含縮圖）
- [ ] 只有該頁的 SVG 被重寫，其他頁檔案的 mtime 不變
- [ ] 只有該頁跑品質檢查
- [ ] **端到端耗時 < 全量重跑的 1/3**（實測數字記錄於此文件底部）
- [ ] 重生成後的 .pptx 在 PowerPoint 開啟正常，未改動的頁面內容與樣式完全一致
- [ ] `current.json` 的選取狀態每次導航／選取都更新，AI 讀取後能正確解析「這一頁」

## 禁止事項

- **不要為了省事把整個引擎流程重寫**——patch 越小，未來合併越容易
- 每新增一個 patched file 都要在 `engine.lock` 登記，並在該處寫明「為什麼覆蓋層做不到」
- 不要破壞既有的全量流程——單頁是額外路徑，不是取代

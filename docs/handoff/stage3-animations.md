# 階段 3：動畫選擇器

> **前置：階段 1 必須完成**（同樣動 `confirm_ui/app.js` 與 `svg_editor/app.js`，且階段 1 是這兩個檔案的偵察）。

## 目標

把引擎既有的 203 個動畫效果從「參數」變成「介面」——**能力已存在，缺的是選擇權**。

## 已查證的事實

| 事實 | 值 |
|---|---|
| 效果註冊表 | `vendor/ppt-master/skills/ppt-master/scripts/pptx_animation_presets.json`（**機器可讀**，選單直接由它生成） |
| 效果數量 | 進場 53 · 強調 33 · 路徑 64 · 退場 53 ＝ **203** |
| 動畫規範 | `references/animations.md`（618 行） |
| 設定檔 | `<專案>/animations.json`，匯出時自動讀取 |
| 動畫錨點 | 頁面上的 top-level `<g id>`——**語意分組已由引擎自動完成**，這是相對 PowerPoint 的結構優勢 |
| 現況缺口 | 確認頁只有一個布林開關，無法挑效果 |

## 兩層設計

**第一層：Deck 套組（主）** — 3 套預設，一鍵套用整份：

| 套組 | 性格 | 建議配置方向 |
|---|---|---|
| 專業沉穩 | 商務簡報 | 淡入為主、無路徑動畫、時長偏短 |
| 輕快活潑 | 內訓／分享 | 適度飛入與縮放、逐項揭示 |
| 極簡無干擾 | 資料密集 | 僅頁間轉場，頁內幾乎不動 |

實際效果配置在本階段決定並記錄於 `overlay/animations/presets.json`。

**第二層：元素微調（輔）** — 在預覽編輯器點元素改效果與進場順序。
**選單每類只放 6-8 個常用效果，不是全部 203**（全塞出來等於重做 PowerPoint 動畫窗格，那是弱點不是賣點）。

**差異化賣點：即時預覽單一元素的動畫** — PowerPoint 必須播放整頁才看得到效果，瀏覽器裡可以點一下就播那一個元素。這是要寫進 README 的東西，優先度高於「效果數量」。

## 工作內容

1. `overlay/animations/presets.json`：三套組的效果配置
2. 確認頁（Stage 2 面板）加入套組選擇 UI
3. 預覽編輯器加入元素層級的效果選擇 ＋ 順序調整 ＋ 單元素預覽播放
4. 產出寫入專案的 `animations.json`（格式須符合引擎契約，見 `animations.md` §2）
5. 改動打包成 `overlay/patches/03-animation-selector.patch`，並在 `engine.lock` 登記

## 驗收標準

- [ ] 三套組可在確認頁選擇，選擇結果正確寫入 `animations.json`
- [ ] 預覽編輯器可點選元素、改效果、調順序
- [ ] 單一元素動畫可即時預覽（不需播放整頁）
- [ ] 匯出的 .pptx 在 **Microsoft PowerPoint** 開啟，動畫行為與預覽一致（PowerPoint 是引擎宣告的主要驗證目標）
- [ ] `animation_config.py validate` 通過
- [ ] 未選任何動畫時，行為與改動前一致（預設 fade 頁間轉場、頁內 none）

## 禁止事項

- 不要把 203 個效果全部塞進選單
- 不要繞過 `animations.json` 契約自己發明格式（匯出器只讀那個）
- 不要改動預設值——沒選動畫的使用者不該感受到任何變化

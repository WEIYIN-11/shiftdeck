# kpi-dashboard（KPI 儀表板）槽位契約

> 讀者是產生 `svg_output/<page>.svg` 的 AI。座標一律是 viewBox `0 0 1280 720` 的絕對值。
> `skeleton.svg` 畫的是 **6 指標（3 欄 × 2 列）**，也就是最密的合法排法；其他張數往下放寬。

## 何時用這個頁型

一頁交代 **3–6 個**同層級的關鍵指標，重點在「現在的水準 ＋ 跟上期比」。

## 固定不動的骨幹

| 項目 | 值 |
|---|---|
| 左右邊距 | 40（內容區 x 40–1240） |
| 欄距 | 24 |
| 3 欄格線 | x = 40 / 448 / 856，欄寬 384 |
| 2 欄格線 | x = 40 / 652，欄寬 588 |
| 標準列 | 上列 y=156、下列 y=398，卡片高 222 |
| 根 `<svg>` | `data-pptx-page-role="content"` |
| 背景 | `<rect id="page-bg" data-pptx-role="background" …>` 全畫布、無圓角無描邊 |

## 槽位表

| `<g id>` | 語意 | `data-pptx-bounds` |
|---|---|---|
| `page-header` | 頁標題 ＋ 期間／範圍一句話 | `40 36 1200 104`（標題 40px @ (40,94)、說明 18px @ (40,126)） |
| `kpi-1` … `kpi-N` | 一個指標卡 | 卡片四邊各外擴 4：`X (Y-4) W (H+8)` |
| `kpi-footnote` | 統計區間、計算口徑、資料來源 | `40 636 1200 44`（14px @ (40, 666)） |

一張卡＝一個 top-level `<g>`＝一個動畫步驟。**不要**把所有卡包成一個 `<g>`。

## 卡片內部座標（X = 卡片左緣，Y = 卡片上緣，W = 卡片寬）

| 元素 | 座標 | 備註 |
|---|---|---|
| 卡片底 | `rect (X, Y) W×H rx16`，`fill=背景`、`stroke=框線` `stroke-width=1` | |
| 強調短棒 | `rect (X+28, Y+28) 44×6 rx3` | 用 `accent` |
| 指標名 | 14px @ (X+28, Y+62) | |
| 數值 | 54px @ (X+28, Y+128) | **只放數字與單位**，例 `00.0%`、`NT$ 0.0M`；不要放中文長句 |
| 期比變化 | 18px @ (X+28, Y+172) | 例「較上期 +0.0」 |
| 進度軌 | `rect (X+28, Y+190) (W-56)×8 rx4`，次面板色 | |
| 進度實績 | `rect (X+28, Y+190) ((W-56)×達成率)×8 rx4`，`accent` | 沒有達成率概念的指標可整組省略 |

標準卡（H=222）內容到 Y+198 為止，下留 24 內距。

## 伸縮規則：指標數 3–6

| 指標數 | 排法 | 欄 x / 欄寬 | 卡片 y / 高 |
|---|---|---|---|
| 3 | 單列 3 欄（加高卡） | 40 / 448 / 856，寬 384 | y=176，高 **400** |
| 4 | 2 列 × 2 欄 | 40 / 652，寬 588 | 上 y=156、下 y=398，高 222 |
| 5 | 上列 3 欄 ＋ 下列 2 欄 | 上 40/448/856（384）；下 40/652（588） | 上 y=156、下 y=398，高 222 |
| 6 | 2 列 × 3 欄（＝骨架） | 40 / 448 / 856，寬 384 | 上 y=156、下 y=398，高 222 |

### 3 指標的加高卡（H=400）多出來的空間

不要讓卡片下半留白，補一個佐證區：

| 元素 | 座標 |
|---|---|
| 分隔線 | y = Y+248（＝424），x 從 X+28 到 X+W-28 |
| 佐證註記 | 14px @ (X+28, Y+280)，一個 `<text>` ＋ 全定位 `<tspan>`，行距 26，**最多 4 行** |

四行的內容建議：目標值與達成率、計算口徑、資料來源與更新頻率、警戒值與負責單位。
只有 2 行可寫時，把卡片高改成 340（y=176，內容到 Y+332 為止），不要留 100px 空白。

### 硬界線

- **少於 3 個**：不要用這個頁型。一兩個數字用「大字報式的單一數字 ＋ 一句解讀」更有力。
- **超過 6 個**：**拆頁**。三種作法，依序考慮：
  1. 先做一頁 3 個核心指標的摘要，明細另開一頁；
  2. 按主題分頁（營收面一頁、營運面一頁）；
  3. 真的都要同級並列時，改用引擎的 `templates/tables/metric_table.svg` 表格形態。

  硬塞 7 個以上會讓欄寬掉到 300 以下，54px 的數值與 14px 的標籤同時失去可讀性，縮圖也認不出是儀表板。

## 字數上限（可用寬 = W−56）

| 位置 | 字級 | 384 欄 | 588 欄 |
|---|---|---|---|
| 指標名 | 14 | 23 字 | 38 字 |
| 數值 | 54 | 6 個半形字元 | 9 個半形字元 |
| 期比變化 | 18 | 18 字 | 29 字 |
| 佐證註記每行 | 14 | 23 字 | — |
| 頁標題 | 40 | 14 字 | |
| footnote | 14 | 85 字 | |

數值放不下時**換單位**（把 1,234,567 寫成 123.5 萬），不要縮字級。

## 字級角色對應

| 角色 | px | 用在 | `spec_lock.md ## typography` 鍵 |
|---|---|---|---|
| title | 40 | 頁標題 | `title` |
| metric | 54 | 指標數值 | 自訂鍵（例 `metric`）——**一定要宣告**，否則同一份 deck 出現第 3 次就是 error |
| body | 18 | 期比變化、頁說明 | `body` |
| annotation | 14 | 指標名、佐證註記、footnote | `annotation` |

本頁型沒有用到 24px；若要加副標，沿用 deck 已宣告的 `subtitle`。

## 佔位色換色表

| 佔位色 | 語意 | 換成 |
|---|---|---|
| `#FFFFFF` | 頁面／卡片底 | `colors.background` |
| `#E8EAED` | 進度軌 | `colors.grid` 的淺階 |
| `#D0D4DA` | 卡片框線 | `colors.grid` |
| `#9AA1AC` | footnote、佐證註記 | `colors.body_text` 的弱化階 |
| `#5A6270` | 指標名、期比變化 | `colors.body_text` |
| `#1F2430` | 數值、頁標題 | `colors.primary` |
| `#4A5568` | 強調短棒、進度實績 | `colors.accent` |

根 `<svg>` 的 `font-family` 換成 `typography.font_family`。

## 禁止事項

- 數值不可用色相單獨表示好壞（紅＝差、綠＝好）。要表達方向就同時給文字（「較上期 +0.0」）或箭頭符號。
- 不要在骨架裡放假數據當真數據。若數字是示意值，依引擎規範在該卡旁加可見的「情境數據」標籤。
- 同段換行只能用 `<text>` ＋ 全定位 `<tspan>`（第一個 `dy="0"`）；不可用兄弟 `<text>` 當同段換行，也不要混寫「直接文字 ＋ tspan」（checker 會判定無法估算版面）。
- 禁止 `mask`、`<style>`、`class`、`foreignObject`、`textPath`、`@font-face`、`<animate*>`、`<script>`、`<iframe>`。
- 文字裡不可出現 HTML 具名實體；`&` `<` `>` 要寫成 `&amp;` `&lt;` `&gt;`。
- 顏色只用大寫六位 `#RRGGBB`。
- 每個 top-level `<g>` 要有 `id` 與 `data-pptx-bounds`；巢狀 `<g>` 不要寫 bounds。

## 何時該建議使用者改用其他頁型

| 情況 | 改用 |
|---|---|
| 同一組指標要比兩個方案／兩個期間 | `comparison` |
| 重點是趨勢走勢而不是當下水準 | 引擎的 `templates/charts/line_chart.svg` / `column_chart.svg` |
| 只有一個指標要強調 | 單一數字大字報頁，不要用儀表板 |
| 指標要跟目標比達成率、且是主角 | `templates/charts/bullet_chart.svg` 或 `gauge_chart.svg` |
| 超過 6 個、且彼此不同層級（有主有次） | 拆成「核心 3 個」＋「支撐指標表格」兩頁 |

## 跨軟體字型度量餘裕（2026-08-12 實測教訓，四個頁型通用）

引擎的字寬估算對**純 CJK 精確**（每字恰為一個 em），但對「CJK＋拉丁字母／空白混排」
**低估約 7-10%**。LibreOffice 的度量比 PowerPoint 更寬，一旦超出文字框就強制重新
斷行、文字掉出方框（對比頁儲存格實際發生過）。因此：

1. 上表的字數上限已含 15% 餘裕，**不要用滿**；行內含拉丁字母或空白時再自扣 2 字
2. 佔位文字與短句盡量用純 CJK 單行；避免「中文 A 中文」這種混排跨行
3. 產出後用 `python scripts/visual_check.py <匯出檔>` 以 LibreOffice 真實渲染逐頁檢查——
   `svg_quality_checker` 只驗幾何估算，抓不到真實字型渲染的撐框

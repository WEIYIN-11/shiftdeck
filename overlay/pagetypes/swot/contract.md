# swot（SWOT 分析）槽位契約

> 讀者是產生 `svg_output/<page>.svg` 的 AI。座標一律是 viewBox `0 0 1280 720` 的絕對值。

## 何時用這個頁型

同時要講**內部條件**與**外部情勢**、而且要分正負兩面。四格的語意是固定的，不是任意 2×2。

## 固定不動的骨幹

| 項目 | 值 |
|---|---|
| 象限數 | **固定 4，不可增減、不可換位** |
| 版位 | 左上＝S 優勢、右上＝W 劣勢、左下＝O 機會、右下＝T 威脅 |
| 語意軸 | 上排＝內部因素、下排＝外部因素；左欄＝正面、右欄＝負面 |
| 欄 | 左 x 40–628（寬 588）、右 x 652–1240（寬 588） |
| 列 | 上 y 156–378（高 222）、下 y 398–620（高 222） |
| 根 `<svg>` | `data-pptx-page-role="content"` |
| 背景 | `<rect id="page-bg" data-pptx-role="background" …>` 全畫布、無圓角無描邊 |

**正負編碼靠底色階，不靠色相**：左欄（正面）底用 `secondary_bg`，右欄（負面）底用 `background`；
強調短棒左欄用 `accent`、右欄用弱化色。不要改成紅綠色相——色相由 lock 決定，而且規範要求
「顏色不可單獨承載必要的區分」，明度差 ＋ 文字標籤才是合規的編碼方式。

|---|---|---|---|

## 象限內部座標（X = 卡片左緣，Y = 卡片上緣）

| 元素 | 座標 |
|---|---|
| 強調短棒 | `rect (X+28, Y+28) 44×6 rx3` |
| 象限名 | 24px @ (X+28, Y+72) |
| 軸註記（例「內部 · 正面」） | 14px @ (X+28, Y+96) |
| 分隔線 | `line` y=Y+112，x 從 X+28 到 X+560 |
| 條目 bullet | `circle (X+34, 基線−6) r3` |
| 條目文字 | 18px @ (X+50, 基線) |

每一條是獨立的 `<text>`（＋自己的 bullet）＝獨立段落，這是合法的兄弟 `<text>`；
但**同一條**要換行時必須用該 `<text>` 內的定位 `<tspan>`。

## 伸縮規則：每象限 2–4 條

| 條目數 | 象限名／軸註記 | 分隔線 y | 首條基線 | 行距 | 末條基線 |
|---|---|---|---|---|---|
| 2 | 名 @ Y+72、軸註 @ Y+96 | Y+112 | Y+150 | 36 | Y+186 |
| 3 | 名 @ Y+72、軸註 @ Y+96 | Y+112 | Y+142 | 32 | Y+206 |
| 4 | 名 @ Y+72、**省略軸註記** | Y+92 | Y+124 | 30 | Y+214 |

- 4 條時省略軸註記，軸向資訊由 `swot-legend` 承擔，不會遺失語意。
- 四個象限**不必等條目數**，但同一頁只用一種行距——挑條目最多那格的行距，四格統一。
- 每象限 5 條以上：拆頁（內部一頁 S/W、外部一頁 O/T），或先歸納成 3-4 條再把細節寫進備忘稿。壓行距硬塞會同時毀掉可讀性與縮圖辨識度。
- 只有 1 條的象限：照樣保留該格與標題，寫「本次未識別出重大 X」，不要留空白格。

## 字數上限

| 位置 | 字級 | 上限 |
|---|---|---|
| 頁標題 | 40 | 14 字 |
| 說明句 | 18 | 60 字 |
| 象限名 | 24 | 18 字（含英文對照） |
| 軸註記 | 14 | 14 字 |
| 條目 | 18 | 29 字（單行，實測上限） |
| legend | 14 | 80 字 |

條目超過 29 字：先砍字；真的砍不掉才用 `<tspan>` 換第二行，此時該象限的條目數上限降為 3（2 條時降為 2）。

**每象限條數的實測邊界（2026-08-15）**：4 條（行距 30）舒適、**5 條（行距 24）可行**、
6 條行間幾乎無間隙、7 條（行距 17）descender 會壓進卡片圓角。第 31 個字會越過卡片框線。

⚠ **條數沒有任何機械檢查在擋。** 實測每象限塞 7 條、行距壓到 17，`svg_quality_checker
--stage final` 仍回報 0 errors 0 warnings 並成功匯出。這裡寫的上限只有你自己會遵守。

## 禁止事項

- 不要改象限位置或語意（例如把 O 放右上）。SWOT 的讀圖習慣是固定的。
- 不要用紅／綠色相區分正負；用底色明度階 ＋ 文字標籤。
- 不要把四格包成一個 `<g>`（會塌成單一動畫步驟），也不要每個 bullet 各開一個 top-level `<g>`（動畫步驟過多）。
- 同段換行只能用 `<text>` ＋ 全定位 `<tspan>`（第一個 `dy="0"`）；不可用兄弟 `<text>` 當同段換行，也不要混寫「直接文字 ＋ tspan」。
- 禁止 `mask`、`<style>`、`class`、`foreignObject`、`textPath`、`@font-face`、`<animate*>`、`<script>`、`<iframe>`。
- 文字裡不可出現 HTML 具名實體；`&` `<` `>` 要寫成 `&amp;` `&lt;` `&gt;`。
- 顏色只用大寫六位 `#RRGGBB`。
- 每個 top-level `<g>` 要有 `id` 與 `data-pptx-bounds`；巢狀 `<g>` 不要寫 bounds。

## 何時該建議使用者改用其他頁型

| 情況 | 改用 |
|---|---|
| 四格但不是 SWOT 語意（優先矩陣、BCG、風險矩陣、effort×impact） | 引擎現成的 `templates/charts/matrix_2x2.svg`，不要套 SWOT 標籤 |
| 只有兩組對照（不分內外） | `comparison` |
| 只想講機會與威脅（外部環境） | 兩欄的 `comparison`，或條列頁 |
| 每格都超過 4 條、資訊量像報告 | 拆成內部頁 ＋ 外部頁兩張 |
| 分析完要接行動方案 | SWOT 之後另開一頁 `flowchart` 或條列頁講對策，不要把對策塞進象限裡 |

## 跨軟體字型度量（2026-08-15 四頁型實測改寫，四個頁型通用）

引擎用固定係數估算文字框寬度：CJK 每字 1.0 em、拉丁與數字 0.55 em。四個頁型各自實測
（微軟正黑體 ＋ LibreOffice）之後，這一節原本寫的「混排一律低估 7-10%」是錯的。真實
情況分三種：

| 情境 | 估算 vs 實際渲染 | 後果 |
|---|---|---|
| 小字級（14-24px）中西混排 | **高估** 7-9%（正黑體拉丁實測約 0.48-0.62 em） | 安全，不必自扣字數 |
| 大字級粗體（40px 以上）拉丁 | **低估** 約 5% | 會溢出，要留餘裕 |
| 多行 tspan 合併成的多段落框 | 上游餘裕 0%（已由 `overlay/patches/06` 補 4%） | 修補前必定斷行 |

**單行與多行的失敗方式不同，這比字數上限重要**：

- 單行 `<text>` → 匯出成 `wrap="none"` 的框，LibreOffice 忽略該屬性，**文字直接溢出
  方框，不會斷行**
- 多行全 `<tspan>` → 合併成多段落框，**會真的斷行**；而且框寬取自「區塊內最寬的
  那一行」

所以多行文字的實務規則是：**讓最寬的那一行是純中文**。若最寬行含數字或英文，就補一
行更長的純中文把框撐開——要修的是別行，不是出問題的那一行（KPI 儀表板的佐證註記實際
發生過：同版型三張卡只有一張爆，因為只有它沒有更長的中文行）。

**字數不是可靠的單位。** 實測 35 字中西混排 ≈ 21 字純中文的寬度。各版型表格的字數上
限是按純中文給的，混排時可以放寬；真正該對的是可用寬度（見各版型的座標表）。

**閘門不會替你把關版面。** 產出後一定要 `python scripts/visual_check.py <匯出檔>` 逐頁
看 PNG。`svg_quality_checker` 只驗「有沒有超出你自己宣告的 `data-pptx-bounds`」，而
bounds 是你自己寫的——實測把兩張卡的 bounds 疊 28px、把 SWOT 每象限塞到 7 條擠爆版
面、讓文字越過卡片框線但仍在 bounds 內，它一律回報 0 errors 並成功匯出。
